# Архитектура

## Принцип

Всё сводится к одному: **у доменов Claude должен быть ровно один выход, и он не должен
уметь падать в «напрямую»**.

Обычные kill switch'и ругают за то, что они режут весь интернет. Здесь наоборот: режется
только путь к Anthropic, а остальной трафик живёт как обычно.

## Поток

```
Claude.app / Chrome / Claude Code
        │  127.0.0.1:2080 (только localhost, снаружи не послушать)
        ▼
   sing-box (шлюз)
        ├─ domain_suffix: claude.ai, anthropic.com, claude.com,
        │                 claudeusercontent.com, statsig*, sentry*,
        │                 challenges.cloudflare.com
        ├─ ip_cidr: 160.79.104.0/21, 2607:6bc0::/32  (сети Anthropic)
        │        → claude-chain → ваш сервер
        └─ всё остальное → direct (обычный VPN или провайдер)
```

`claude-chain` — это `selector`, а не `urltest`. Автопереключения нет специально:
смена страны посреди сессии выглядит для сервиса хуже, чем короткая пауза.

## Почему Shadowsocks, а не только REALITY

Проверено на практике: VLESS+REALITY работает с Xray-клиентами, но **не проходит через
туннель Happ** — он нормализует ClientHello и подпись REALITY ломается. Обычный TLS при
этом проходит, а Shadowsocks-2022 проходит стабильно.

Поэтому в типовой схеме:

| Клиент | Протокол | Порт |
|---|---|---|
| Mac за туннелем Happ | Shadowsocks-2022 | 8443 |
| телефон, чужие сети | VLESS + REALITY | 443 |

Оба inbound'а живут в одной панели и управляются из одного места.

## DNS

Домены Claude резолвятся через DoH **внутри туннеля**, а не локальным резолвером. Это
убирает подмену DNS провайдером и не даёт утечки запросов. Остальные домены — через
локальный резолвер, как обычно.

## Защита от утечки

1. **Маршрут.** У Anthropic-доменов нет варианта `direct` в цепочке.
2. **Фаервол.** Прямые соединения к `claude.ai` и `*.anthropic.com` запрещены всем
   процессам (Little Snitch или аналог).
3. **Песочница.** Claude Code запускается в `sandbox-exec` с профилем, где разрешён
   только localhost.
4. **Сторож.** Периодически проверяет, что Claude Desktop запущен с нужным прокси, и
   перезапускает его правильно.

## Измерения

- `claude-net trace` — `cloudflare.com/cdn-cgi/trace` через цепочку и напрямую.
  Настоящий ответ на вопрос «что видит Anthropic».
- `claude-net check` — четыре точки: прямой выход, выход цепочки, `claude.ai`,
  `api.anthropic.com`.

Важно: `/cdn-cgi/trace` у `api.anthropic.com` и `claude.ai` отдаёт **константу**, а не
адрес клиента. Проверять маршрут по нему нельзя — только по `cloudflare.com`.
