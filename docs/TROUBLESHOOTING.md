# Если что-то не работает

Начинайте с двух команд — они отвечают на 90 % вопросов:

```bash
claude-net status
claude-net trace
```

## Шлюз не поднимается

```bash
claude-net start
launchctl print gui/$(id -u)/com.claude-net.gateway | head -20
tail -20 ~/vpn/claude-net/sing-box.log
```

Частые причины:

- **`exit 78 (EX_CONFIG)`** — процесс не смог прочитать конфиг. Так бывает, если папка
  лежит в `~/Documents`, `~/Desktop` или `~/Downloads`: macOS защищает их (TCC), и
  фоновый процесс не получает доступ. Держите проект в `~/vpn` или
  `~/Library/Application Support`.
- **порт занят** — `lsof -iTCP:2080`. Два экземпляра шлюза конфликтуют.
- **конфиг битый** — `sing-box check -c config.json`.

## Claude Desktop уходит не туда

```bash
claude-desktop --check     # видит ли шлюз Сингапур
claude-desktop --restart
```

Проверка, куда реально идут соединения:

```bash
lsof -nP -iTCP | grep -i claude | awk '{print $9}'
```

- `127.0.0.1:2080` — правильно, идёт через шлюз;
- `127.0.0.1:1082` (или другой порт VPN-клиента) — приложение взяло системный прокси и
  пошло мимо.

## Прямой доступ к Anthropic не блокируется

Проверка:

```bash
curl -sS -m 5 -o /dev/null -w '%{http_code}\n' https://api.anthropic.com/
```

Должно быть `000`. Если `401` — фаервол не настроен, трафик может утечь.

## REALITY не подключается

Симптом: `reality verification failed`.

1. Убедитесь, что серверный `private_key` и клиентский `public_key` — одна пара.
2. Проверьте, что `short_id` и `server_name` совпадают.
3. Если соединение идёт через туннель другого VPN — попробуйте другой протокол
   (Shadowsocks-2022): некоторые сети ломают REALITY-хендшейк.

## Подписка отдаёт 404

Разные панели используют разные пути. Проверьте `subPath` в настройках панели — путь
из настроек и путь в ссылке должны совпадать символ в символ.

## Claude Code в песочнице не видит сеть

Так и задумано: в профиле `sandbox/claude-code.sb` разрешены только соединения на
localhost. Если нужен доступ к чему-то ещё — расширяйте профиль осознанно.
